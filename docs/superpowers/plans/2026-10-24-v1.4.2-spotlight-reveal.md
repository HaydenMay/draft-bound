# Spotlight Reveal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Add a responsive, accessible team-to-receiver spotlight reveal before each manual v1.4.2 receiver potential choice.

**Architecture:** Keep all gameplay outcome selection in `domain/engine.ts`. Add a pure helper for decorative spotlight paths and a reusable standalone Angular presentation component that owns only reveal timing and stage transitions. Integrate it at the existing app-level reveal boundary so the component's completion/skip clears presentation state without dispatching a game command.

**Tech Stack:** Angular 21 standalone components/signals, TypeScript, CSS, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-24-v1.4.2-spotlight-reveal.md`.

## Global Constraints

- Preserve existing domain team/receiver selection, Quick 3 and Full 8 manual-pick counts, and Quick autofill behavior.
- Use current catalog team codes/names and eligible receiver names; do not add/hotlink logos, art, sounds, or animation dependencies.
- Keep game saves and gameplay rules unchanged; spotlight animation is cosmetic and must not touch the game RNG.
- Respect `prefers-reduced-motion`, keyboard/touch use, accessible names, light/dark themes, and narrow mobile widths.
- Preserve GitHub Pages `/draft-bound/` compatibility and project-specific UI/content guidance in `AGENTS.md`.

## Review Focus

- Outcome independence: changing or skipping the decorative path must leave the predetermined receiver and game RNG unchanged; cover with pure-helper and existing domain tests.
- Repeated board entries: random path must avoid immediately spotlighting the same tile twice when there are alternatives; cover in helper tests.
- Sparse pool: one eligible receiver must bypass a faux receiver competition; cover through a pure stage-plan test and catalog data.
- Rapid skip/stage completion: only one completion may occur and no timeout may fire after teardown; cover through component lifecycle and browser skip checks.
- Accessibility settings: reduced motion and mobile viewport must still expose the selected result and controls; cover with Playwright media/viewport assertions.
