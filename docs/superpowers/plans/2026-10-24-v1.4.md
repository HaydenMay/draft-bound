# Draftbound v1.4 implementation plan

**Spec:** `Draftbound_v1.4_Implementation_Spec.md` (owner-provided implementation handoff)
**Baseline:** `7fbee924894217052d14d6a83eeb04b469bccfe8`
**Branch:** `codex/v1.4`

## Global constraints

- Ship v1.4 only; no v1.4.1, v1.5, or v2 features.
- Keep old career results, unfinished runs, draft cards, unknown positions, and v1.3.1 JSON fixtures immutable and usable.
- Version new professional rules and source catalog independently, with missing markers dispatching to legacy.
- No changes to college RNG/growth, recruiting, current ceiling semantics, team branding, legal gates, services, or artwork.
- TDD each behavior change; run unit, E2E, build, and reproducible balance checks.

## Tasks

1. Freeze v1.3.2 baseline reports and representative old career simulation results; inspect all catalog, save, store, UI, and test interfaces.
2. Centralize collection achievement definitions, safe progress projections, and cosmetic rewards; add accessible binder achievement destination and locked-frame route; make HOF-based Legend additive and immediate.
3. Freeze source definitions/pool for legacy active runs; document grading rubric and audit evidence; make targeted S-grade corrections and catalog additions only where supported; test old pending offers and new catalog selection.
4. Add explicit professional rules version dispatch, preserving old simulator exactly; implement and calibrate new deterministic career algorithm; freeze already-simulated careers.
5. Correct development explanations in relevant UI without changing mechanics or RNG.
6. Add compatibility, balance, audit, release, and v1.4.1 forward-architecture reports; perform mobile/theme/accessibility/browser verification.
7. Final full verification and whole-branch review; commit and push to `main` only when gates pass; verify Pages deployment.

## Review focus

- Old saves and pending choices retain their original source grades and RNG behavior.
- Career rules dispatch by the draft's saved version; no existing career is resimulated.
- Achievement IDs, frames, foil validation, and card customization remain additive and monotonic.
- HOF and All-Pro are calibrated from evidence, not a coin flip or prospect nerf.
- User-facing descriptions are accurate, accessible, concise, and don't imply future systems.

## Completion checks

`npm run typecheck`, `npm test`, `npm run test:e2e`, `npm run build:pages`, `npm run balance`, `npm run balance:paired`, targeted compatibility/balance scripts, desktop/mobile visual review, final review, commit/push and Pages status.
