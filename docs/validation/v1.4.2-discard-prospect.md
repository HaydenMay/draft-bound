# Discard-current-prospect follow-up

Owner-requested usability change, October 24, 2026.

## Behavior

- Expose **Discard current prospect** near the top of Settings whenever an active, unfinished prospect exists. The action identifies that prospect by name.
- Open a separate confirmation before removing anything. Keep prospect returns to Settings. Confirming removes only the active run and opens the New prospect form; binder entries, favorites, unlocks, and settings remain saved.
- Save the envelope with `run: null` before clearing the in-memory run. A write failure leaves the original prospect intact and keeps the confirmation open with an error. The existing binder-start-new discard flow uses the same safe operation.
- Preserve unreadable-save protection, concurrent-tab protection, and the existing binder-capacity guard when starting a new prospect. No save-schema migration is required.
